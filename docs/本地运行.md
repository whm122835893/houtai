```bash

composer install          # 官方 packagist 源（阿里云镜像缺 topthink/framework 8.1.4，勿用）

# 5. 建表：先框架系统表（迁移），再业务表

mysql nft < database/nft.sql

# 6. 管理员密码（种子默认密码未知，重置一次）
#    临时脚本：new \app\admin\model\Admin())->resetPassword(1, '123456');

# 7. 前端构建 + 发布
cd web && npm run build
cp -r web/dist/index.html web/dist/assets public/
echo 'install-end' > public/install.lock

# 8. 启动
php think run --host 0.0.0.0 --port 8787
# 访问 http://127.0.0.1:8787/admin  （admin / 123456）
```

## 多 C 端开放 API（2026-11-07 追加）

以本后台为唯一后端，为各 C 端实例（第一个：zhenhaiQZ 臻海）提供源站路径一致、前端零改动的 HTTP API。最小闭环：注册登录 → 藏品目录 → 下单 → 余额支付 → 订单 → 持仓。

### 架构约定

- **服务层**：业务事务逻辑统一在 `app/common/service/nft/`（Wallet/User/Collection/Hold/Order），admin 与 api 两个入口共用，控制器保持薄。
- **鉴权**：`app/api/middleware/BearerToken.php` 把 `Authorization: Bearer <token>` 映射为 `ba-user-token`，完全复用 BuildAdmin 会员鉴权（`app\common\library\Auth`）。
- **响应契约**：`app/api/middleware/CStyleResponse.php` 按 `config/nft.php → c_end_style` 适配包络：
  - `zhenhai`（默认）：`{status, code, message, data}`，恒 HTTP 200，code 0=成功、11111=未登录、10100/10101=参数、10203=未找到、20000=业务失败；
  - `standard`：BuildAdmin 原生 `{code, msg, time, data}`（供后续 qbox/sinan 实例按需选择）。
- **金额**：一律「分」落库与传输；时间：13 位毫秒字符串。

### 配置（.env）

```ini
[C_END] 也可直接写环境变量
C_END_STYLE = zhenhai          # 该实例对接的 C 端契约风格
NFT_SMS_DEBUG = true           # 调试模式：短信验证码固定 123456（生产必须 false 并接短信网关）
NFT_RSA_PUBLIC  = <RSA 公钥>    # C 端密码 RSA(PKCS1) 加密传输；openssl genrsa -out rsa.key 2048 && openssl rsa -in rsa.key -pubout -out rsa.pub
NFT_RSA_PRIVATE = <RSA 私钥>
```

> RSA 公钥由 `GET /api/passport/captcha/image` 下发给 C 端，私钥留后端解密；未配置且调试模式下允许明文（仅本地）。

### 二级市场
- **寄售单** `market_order`：0=在售 1=已售 2=已下架 3=已锁定（下单即锁防双卖）；取消订单自动解锁。
- **订单类型**（order.type → 源站 order_type）：1→10 常规 / 2→20 市场 / 3→21 批量 / 4→22 求购 / 5→23 委托。
- **资金**：市场成交扣 6% 综合服务费，卖方实收 `floor(价格×0.94)`；求购/委托支付后金额进买方 `frozen` 托管，按件释放给卖方。
- **过户**：卖出方原持仓置 `hold.status=3 已转出`，买入方生成新凭证（`source=2`，`ref_id`=订单号）。
- **委托撮合**：寄售时自动与「出价 ≥ 寄售价」的委托单按出价从高到低成交，成交价=委托出价。
- **二级密码**：寄售/求购出售须验二级密码（`PUT /passport/secondPassword` 设置，md5 存储；未设置时放行，仅限本地调试）。
- 市场浏览接口（`/nft/secondary*` 除 follow）未登录可访问；持仓、寄售、关注需登录。

### 冒烟路径（/tmp/smoke_market.sh）
寄售→市场列表→单件/快捷/批量买入→过户→求购(托管)→出售给求购→委托(撮合)→下架→取消解锁→关注→二级密码→订单分型查询→出售记录→公告，31 步账目核对通过。

## 超时关单任务（2026-11-08 追加）
### 部署（系统 cron，每分钟一次）
```cron
* * * * * cd /path/to/houtai && php think order:close >> runtime/log/order_close.log 2>&1
```

### 行为
- `app/command/OrderClose.php`（`php think order:close [--limit N]`，默认单次 200 条）。
- 关闭 `status=0 且 createtime ≤ now-900s`（15 分钟支付窗口，`OrderService::PAY_WINDOW`）的订单为 `status=2`，并解锁其占用的寄售单（`market_order.status=3 → 0`，`order_id` 清零）。
- 并发安全：关单 UPDATE 带 `status=0` 守卫，与在线支付（行锁互斥）不会误关已支付订单。

### 验证结论（本地 8787 实测）
| 用例 | 结果 |
| --- | --- |
| 过期订单（createtime=now-1000s） | 关闭为 status=2 |
| 未过期订单（createtime=now） | 不受影响，保持 status=0 |
| 关单后寄售单解锁 | market_order 3→0、order_id 清零，可被再次买入 |
| 幂等重跑 | `no expired orders`，状态无变化 |
| `--limit 1` 分批 | 每轮仅关 1 条，多轮收敛 |

## RSA 密码加密配置（2026-11-08 追加）

### 配置（.env，已 gitignore 不入库）
```ini
NFT_SMS_DEBUG = true    # 生产置 false：明文密码将被拒（10101），短信需真实网关
NFT_RSA_PUBLIC  = <base64 裸公钥，单行>
NFT_RSA_PRIVATE = <base64 裸私钥（PKCS8），单行>
```
生成：`openssl genrsa -out rsa.key 2048 && openssl rsa -in rsa.key -pubout -out rsa.pub`（各去头尾行拼成单行）。

### 链路
1. `GET passport/captcha/image` 下发 `publicKey`（后端自动把裸 base64 规范化为 PEM，私钥/公钥头部类型区分）。
2. C 端 RSA(PKCS1) 加密密码 → `passport/signin|signup`、`nft/sell/*` 的 `secondPassword` 等。
3. `Cbase::decryptPassword()` 私钥解密；解密结果含控制字符（乱码）一律按解密失败拒（10101），防止合法 base64 的短字节数据流进登录比对。
4. 调试模式（`NFT_SMS_DEBUG=true`）密钥解密失败时明文兜底，便于本地联调。

### 验证结论（本地 8787 实测）
| 场景 | 生产模式（sms_debug=false） | 调试模式 |
| --- | --- | --- |
| RSA 密文注册 → 登录 | 通过 | 通过 |
| 明文密码 | 拒绝（10101 密码解密失败） | 兜底放行 |
| 非法密文 | 拒绝（10101） | 拒绝（10101） |

### 多 C 端说明
密钥对属后端实例配置；C 端公钥经 `captcha/image` 动态下发，任意数量 C 端对接或更换密钥，C 端代码零改动。多实例部署建议各实例独立生成密钥对（隔离风险）。

## 活动 / 合成 / 盲盒 / IM 分包（2026-11-08 追加）

### 接口（zhenhaiQZ 页面级真实调用，未调用不做）
| 接口 | 说明 |
| --- | --- |
| `GET /activity/sign` | 签到状态 `{signDays, records[当月布尔数组]}` |
| `POST /activity/sign` | 每日签到 +10 积分（重复签到 20000） |
| `GET /activity/points/balance` | 积分余额 `{balance}` |
| `GET /activity/lottery/active` | 进行中抽奖活动（无活动 data=null → 前端「敬请期待」） |
| `POST /activity/lottery/start/{id}` | 抽奖，概率百分比加权随机，返回 `{id:中奖奖品id}` |
| `GET /activity/lottery/log` | 抽奖记录裸数组 `[{imageUrl,name,createTime}]` |
| `GET /item/merge` | 合成活动列表卡片（total/surplus/rangeTime/stateText） |
| `GET /item/merge/{id}` | 合成详情（needs[].ownQuantity 登录态计算；endTime/mergeTime 毫秒字符串） |
| `POST /nft/merge/v1` | 合成兑换 `{mergeId, nftIds}` → `{imageUrl,name,quantity}` |
| `POST /nft/box/open` | 盲盒开启 `{nftId}` → `{imageUrl,name,token,total,nftId}` |
| `GET /im/group` | 群列表 `[{id,name,avatar,isJoin}]` |
| `POST /im/group/join/{id}` | 加入群组（幂等恒 true） |

### 口径
- **积分**：`user.points`，签到每日 10 分（`activity_sign.points` 留快照）。
- **抽奖**：`activity_lottery_prize.probability` 百分比（前端展示「中奖率: x%」），万分比权重随机；`collection_id>0` 中奖自动发凭证（source=4）；积分不足/发放失败整体回滚不扣分。
- **合成**：`item_merge`（output_collection_id=产出物）+ `item_merge_need`（材料×数量）；材料凭证消耗置 `hold.status=5`，剩余量原子扣减防超发；材料数量与所选凭证须完全一致。
- **盲盒**：`collection.type=2` 的凭证可开启；奖池复用 `blindbox_prize`（box_id=collection.id，万分比概率，sent<quantity 守卫库存）；原凭证置 `hold.status=4`，新凭证 source=7；`/nft/{id}` 的 `item.type` 已按藏品 type 下发（前端据此显示「开启」按钮）。
- **IM**：`im_group` / `im_group_member`；群列表免登录（isJoin 未登录恒 false）。
- **hold 状态口径追加**：4=已开启(盲盒) 5=已合成(材料)；**source 追加**：7=盲盒开启。

### 数据库
nft.sql 第八章：activity_sign / activity_lottery / activity_lottery_prize / activity_lottery_log / item_merge / item_merge_need / item_merge_log / im_group / im_group_member + ALTER user.points、collection.type。已有库需手工执行第八章段落（重复执行报 Duplicate column 属正常）。

### 冒烟结论（本地 8787 实测，RSA 登录链路）
签到→积分+10→重复签到报错；充 200 分抽 4 次（20%/1% 藏品奖均命中）→ 余额精确归零 + 中奖凭证入账；造材料（A×2+B×1）合成→材料 status=5、新凭证 collection 4、surplus 10→9、hold_count 3 精确；盲盒开盒→30% 抽中隐藏款、原凭证 status=4、新凭证 source=7、sent 记数；IM 加入幂等、isJoin 翻转；未登录 11111 / 不存在群 10203 / 再合成与再开盒均正确拒绝。

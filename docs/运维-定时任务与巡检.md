# 运维手册：定时任务与巡检

> 更新时间：2026-11-12
> 适用：BuildAdmin 数藏后台（本仓库）
> 沙箱内三件套已实装并实测，生产环境按本文照抄即可。

---

## 一、任务总览

| 任务 | 命令/脚本 | 频率 | 作用 |
|------|-----------|------|------|
| 业务维护 | `php think nft:maintain` | 每分钟 | 藏品售罄自动置位（库存池归零/超截止时间 → status=4）；待支付订单超时取消（默认 15 分钟，后台「设置」可调 `order_auto_cancel`） |
| 数据库备份 | `bash scripts/backup-db.sh` | 每日 03:30 | mysqldump 全量 gzip 到项目 `backups/`，默认保留 14 天 |
| 数据巡检 | `php think nft:check` | 每日 04:05 | 钱包账本自洽/余额衔接/余额终点/收支汇总、库存池口径非负、孤儿持仓、负余额；FAIL 时退出码 1 |

## 二、生产环境安装

```bash
crontab -e
# 粘贴 scripts/crontab.example 内容（把 /www/wwwroot/buildadmin 改为实际部署目录）
```

要点：
- `nft:maintain` 必须每分钟一次，保证售罄/超时取消及时
- 巡检退出码非 0 时建议接告警（企微/钉钉机器人），示例见 crontab.example 末尾
- 备份目录 `backups/` 在项目内，**务必配置服务器异地备份**（如 rsync 到对象存储/另一台机器），防止磁盘故障连备份一起丢

## 三、巡检项明细（nft:check）

| 编号 | 检查项 | 判定 | 级别 |
|------|--------|------|------|
| A1 | 流水自洽：每条 wallet_log 满足 `after = before + amount` | 不满足 | FAIL |
| A2 | 余额衔接：同用户流水中 `前一条.after = 后一条.before`（外部支付记账 before=after 自动跳过） | 断链 | FAIL |
| A3 | 余额终点：`user.balance` = 该用户最后一条流水的 `after` | 不等 | FAIL |
| A4 | 收支汇总：`total_income/total_expense` 与流水正负额汇总一致 | 不等 | FAIL |
| B1 | 原始池非负：`stock - sold - 空投净发 - 置换发 - 盲盒奖池 - 销毁 + 回收 >= 0`（不经 max(0) 修正） | 超发 | FAIL |
| B2 | 发放与持仓：应发口径 vs hold 实际记录数 | 差异仅提示（市场购不占池等属正常） | WARN |
| C1 | 孤儿持仓：hold 指向不存在的藏品 | 存在 | FAIL |
| C2 | 负余额：`user.balance < 0` | 存在 | FAIL |

退出码：`0` = 全部通过；`1` = 存在 FAIL。

## 四、验证记录（沙箱实测 2026-11-12）

- `php think nft:maintain`：正常输出「本轮置位 0 个 / 取消超时订单 0 笔」
- `php think nft:check`：空库全 OK，退出码 0
- 破坏性验证：造用户充值 100 元消费 30 元（余额 70 元），篡改 `balance=9999` → **A3 精确抓取**；篡改末条流水 `after+1` → **A1 精确抓取**；均退出码 1
- 验证后测试数据已全部清理

## 五、故障处置速查

| 现象 | 排查 |
|------|------|
| A2/A3 断链 | 多半是并发写余额未走 `NftTrade::walletMove`（事务+行锁），检查绕过记账的直接 update |
| B1 超发 | 检查是否有代码路径发藏品未走库存池扣减（`NftTrade` 统一入口） |
| 备份文件为 0 字节 | mysqldump 失败，看 `runtime/log/backup.log`；确认 `.env` 凭据与磁盘空间 |
| cron 未生效 | `service cron status`；`grep CRON /var/log/syslog` 看执行记录 |
